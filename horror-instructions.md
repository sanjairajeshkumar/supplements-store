## General Rules
- Always write clean, readable, and well-structured code
- Use proper indentation and formatting
- Use meaningful and descriptive names for classes and elements
- Avoid unnecessary complexity

## HTML Rules
- Always use semantic HTML tags (header, section, article, footer, nav)
- Maintain proper nesting of elements
- Avoid using too many divs when semantic tags are available
- Add comments for major sections (e.g., Header, Hero Section, Footer)

## CSS Rules
- Always use a separate CSS file (no inline styles)
- Use class selectors instead of IDs for styling
- Follow consistent naming conventions

## Naming Conventions
- Use snake_case for class names (e.g., hero_section, feature_card)
- Class names should reflect their purpose (e.g., header_nav, footer_links)
- Avoid generic names like box, item, div1

## Layout Rules
- Use Flexbox for layout by default
- Use CSS Grid only when necessary
- Ensure proper spacing between elements (margin and padding)

## Responsive Design
- Always make the layout responsive
- Use media queries for mobile, tablet, and desktop
- Ensure elements stack properly on smaller screens

## UI/UX Rules
- Keep design clean and minimal
- Use consistent spacing throughout the layout
- Use readable font sizes
- Add hover effects for interactive elements (buttons, links)

## Best Practices
- Reuse components where possible
- Keep CSS modular and organized
- Avoid duplicate code
- Optimize for readability over cleverness

## Vanilla JavaScript Rules

Use only Vanilla JavaScript unless a framework or library is explicitly requested
Do not use external JavaScript libraries or frameworks
Use modern JavaScript (ES6+) syntax
Use DOM APIs for interacting with HTML elements
Use querySelector or querySelectorAll for selecting elements
Use addEventListener for handling events
Avoid inline JavaScript such as onclick, onchange, or onsubmit
Keep JavaScript in a separate .js file
Use classList for adding, removing, and toggling CSS classes
Use textContent instead of innerHTML when inserting plain text
Validate user input on the client side where appropriate
Handle form submission using JavaScript event listeners
Prevent default form submission when custom validation is required
Keep DOM manipulation simple and readable
Avoid unnecessary DOM queries and repeated code
Create reusable functions for repeated logic
Handle edge cases and invalid user input gracefully
Do not mix HTML, CSS, and JavaScript unnecessarily
